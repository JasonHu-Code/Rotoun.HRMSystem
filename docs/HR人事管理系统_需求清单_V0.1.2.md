## 二、需求清单使用方法

- **编号规则**：`HR-域代码-序号`。后续设计文档、接口、测试用例、任务拆解一律引用编号。
- **优先级**：**P0** = v1.0 必须上线（**上限 80 条**）；**P1** = 上线后首迭代；**P2** = 二期或按需。
- 共 **14 个业务域 + 1 个考勤机对接专项**，合计 **241 条**：P0 **80** 条、P1 **132** 条、P2 **29** 条。

> **P0 裁剪已执行（修订 3、4、5、7）**：P0 从 112 条压到 **80 条**，v1.0 范围不变；修订 7 新增 46 条全部为 P1/P2，故 P0 在 241 条总量中占比降至 33%，仍控制在设定上限内。原则是"缺了系统跑不起来"才是 P0——报表、台账、附件、导出、续签这类"重要但不阻塞"的一律下压到 P1。
>
> **P0 分布**：考勤 17、薪酬 13、组织 9、员工 9、系统权限 9、迁移治理 7、入转调离 6、假期 4、合同 3、社保 2、绩效 1、**打卡机对接 0**（合计 80）。

## 四、考勤机对接专项（HR-DEV）

> **本域整体定为 P1，v1.0 不做接口直连。**
> v1.0 上线期的打卡数据由 `HR-ATT-29 考勤数据文件导入` 承接：从考勤机厂商后台导出 Excel 导入。**原始流水表的数据模型不变**（只加"数据来源"字段），P1 接上接口后直接替换入口，不用改表、不用改考勤计算。
>
> **人员主数据方向已确认：HR 为唯一数据源。** 打卡机平台里的员工从 HR 获取，不由打卡机反向往 HR 写人。对应 `HR-ATT-30`：入职/调岗/离职生成"待同步"任务，P1 阶段向得力等平台写入人员并设 `ext_id=工号`。

### 4.1 采集模式（P1 实施时按此设计）

已确认集团在用**得力**，且**还有其他品牌并存**。这两类设备的取数方向是相反的，不能只做一种：

| 模式 | 适用 | 数据流向 | 谁主动 |
|---|---|---|---|
| **A. 设备推送（Push）** | 熵基 ZKTeco 等支持 ADMS 的设备 | 设备 → HR 服务器 | 设备主动 POST |
| **B. 云平台拉取（Pull）** | **得力 e+**（已确认在用） | HR 服务器 → 得力云 API | **我们的服务主动拉** |
| **C. 设备轮询（Polling）** | 不支持 Push 的老设备 | 厂区中间件 → 设备 | 中间件定时拉 |

得力 e+ 的公开接口（`doc.delicloud.com`，企业开放平台）：

- 地址：`POST /v2.0/cloudappapi`
- 认证头：`App-Key` / `App-Timestamp` / `App-Sig`
- 请求体：`Api-Module=CHECKIN`、`Api-Cmd=checkin_query`、`next_id`、`page_size`
- 返回：`id`、`user_id`、`ext_id`、`terminal_id`、`check_type`、`check_time`、`check_data`
- 游标：`next_id` **非连续**，必须原样保存上次返回值
- **硬限制：只能取"考勤数据初始化接口调用之后新产生"的记录，查不到历史**

**这条限制很要命**：得力的历史数据在接口侧拿不到。上线前必须先调初始化接口把游标归零，否则中间产生的数据只能靠手工补。

## 五、关键设计判断（需你认可）

### 1. 不做分库，做组织维度数据权限
数据量 302 人、单库无压力；分库会让集团汇总报表、跨法人调动、成本分摊全部变成跨库查询。用单库 + `company_id` / `org_id` + 组织树数据权限即可。

### 2. 原始打卡流水与考勤结果必须两张表
流水只追加、永不修改；考勤结果由规则算出、可重算。合成一张表，一旦有人改数，原始依据就没了。

### 3. 组织架构必须带版本 + 生效日期
实测资料里历史任职为空，说明老系统没做这件事。新系统必须从设计阶段就带上，后补极难。

### 4. 职级必须双表：职级定义 + 公司职级映射
E2 在集团是副总经理、在子公司是总经理。做成一张全局表，跨法人调岗时薪级和审批权限必然对不上。

### 5. 计件工资单独建模，不塞进通用薪资项
计件是"产量 × 单价"的明细计算，必须能追溯到"某人某天做了哪道工序多少件"。只留一个金额字段，车间主任问"这数怎么算"就答不出来。

### 6. 考勤的个人差异走排班，不走"个人规则副本"
规则层可以配到个人，但个人级的"时段和工作日"必须由排班产生。否则 302 人配出 200 套规则，三个月后没人说得清谁按什么算，考勤争议时无法自证。

### 7. 工作日历与排班日必须分离
个人可以"周六上班"，但那是休息日加班（2 倍）。把工作日历和排班合成一个字段，等于给企业开了合法规避加班费的后门——劳动仲裁必输。

### 8. 多组织不等于多租户
你的多组织是集团内部，数据可互相看见、只是权限收窄。按 SaaS 多租户设计会导致跨组织报表写不出来。

### A.3 定级规则（建议，供评审）

- **按岗位定级，不按人定级**：先给职位定级，再把员工挂到职位上。避免"同岗位同职责、两个人两个级"。
